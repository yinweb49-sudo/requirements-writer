# <项目名> · 需求文档编写项目档案（requirements-profile）

> 本文件供 `requirements-writer` skill 读取，把通用模板里的占位符替换成本项目真实术语。
> **新项目开一次、填完即可**。建议复制到项目仓库根、`.agents/` 或 `docs/` 下，命名为 `requirements-profile.md`。
> 填不清楚的先留空或写“无 / 单体”；skill 会按缺省情形裁剪结构，不会硬套不存在的层。

## 基本信息

- 项目名称：
- 仓库根说明文件：`README.md` / `docs/项目索引.md`（skill 会先读它了解全局）
- 产品视角 / 沟通约定（可选）：例“先说业务再说技术、面向产品同学”

## 架构分层（占位符 → 本项目真实名）

| 占位符 | 本项目对应 | 说明 |
|---|---|---|
| `{{前端}}` |  | 例：`web`（React + Vite）/ `app`（移动端）；纯后端项目填“无” |
| `{{本地后端}}` |  | 例：`api-server` / 本地服务；单体后端也填这一格 |
| `{{云端后端}}` |  | 例：云端 / ERP 后端；无云端填“无” |
| `{{运行档位机制}}` |  | 例：一个开关切数据库 / 服务注册 / 白名单；无档位填“无” |

> 系统实际是几层就填几层。单体项目只填 `{{本地后端}}` 一格，其余写“无”。

## 数据库

| 占位符 | 本项目对应 |
|---|---|
| `{{主库}}` | 例：SQLite（本地）/ PostgreSQL / MySQL |
| `{{次库}}` | 例：SQL Server（云端）；单库填“无” |

- 用户隔离字段：例 `OwnerType` / `UID`
- 加列 / 建表约定：例 幂等建表 / `ALTER ADD COLUMN` / 迁移工具用法与注意点

## 鉴权与白名单术语

- `{{鉴权方案}}`：例 某种 scheme / JWT / Session / 单一鉴权
- `{{白名单机制}}`：例 按运行档位暴露控制器的白名单类；无则填“无”
- 计费机制：例 算力扣费 / 积分；无计费填“无计费”

## 验收 / 调试方式

- `{{验收方式}}`：例 某个本地调试 skill / `npm run dev` / `docker compose up` / 手动起服务

## 结构检索工具

- `{{结构检索工具}}`：例 CodeGraph（`codegraph_*`）/ 或“grep + 文件读取”

## 样本文档（本项目已有的好范例，供 skill 学结构）

- 主需求文档样本路径：例 `docs/xxx/xxx-开发需求文档.md`
- 分期提示词样本路径：例 `docs/xxx/开发提示词/README.md`、`期1-*.md`
- 若还没有样本：填“暂无，按 skill 内置模板结构写”

## 文档产出位置约定

- 默认放：`docs/<功能名称>/`（可改）

## 端口 / 目录约定（可选）

- 例：前端 dev 端口、后端端口、各前端产物目录……写清避免 AI 猜错。
