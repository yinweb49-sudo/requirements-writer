# 需求文档 / 开发提示词 评审清单

对照模板逐条核对，发现问题就指出位置和改法。带 `{{}}` 的术语按**项目档案**取值；项目没有的机制（多库 / 白名单 / 计费 / 云端层）对应条目跳过，不因缺失判为不合格。

## 主需求文档
- 11 节齐全（按项目实际裁剪）：背景目标 / 关键决策 / 架构 / 功能交互 / 复用弃用 / 数据模型 / 接口 / 技术选型 / 分期 / 已确认决策 / 风险。
- 关键决策每条有理由；已确认与待确认分开，未验证的不写成结论。
- 架构分层与密钥归属写清，密钥不下发到不该有的层。
- 数据模型有用户隔离与加列 / 建表方式（按 `{{主库}}` / `{{次库}}` 的实际约定）；接口有鉴权方案（`{{鉴权方案}}`）、白名单（`{{白名单机制}}`，如有）、是否计费。

## 开发提示词
- 一期一文件；每期含 目标 / 动手前必读 / 前置状态 / 任务清单 / 数据模型 / 约束 / 验收。
- 每期能独立验收（含“重启不丢、按用户隔离”等回归）；明确本期不做什么。
- 引用的需求文档与代码模板路径真实存在。

## 通病
- 无“一律 / 全部”式一刀切；多平台 / 多档位分情况。
- 区分产品能力与实现手段，未把换手段说成砍功能。
- 参考项目 / 竞品的判断有代码 + 行号佐证，非凭 README / 片段。
- 未自创结构，沿用现有目录、命名、组件、端口（以项目档案与仓库现状为准）。
