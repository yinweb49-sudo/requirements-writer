# 分期开发提示词模板

用这个模板写 `开发提示词/README.md` 和 `期N-*.md`。目标是让每期能单独开窗口执行，AI 读完就知道要看什么、改哪里、不能碰哪里、怎么验收。

> **术语替换（先读）**：占位符 `{{前端}}`、`{{验收方式}}`、`{{结构检索工具}}`、`{{主库}}`、`{{次库}}`、`{{鉴权方案}}`、`{{白名单机制}}` 从**项目档案**取真实值替换；项目没有的机制就删掉对应句子，不硬套。

## 开发提示词 README

```markdown
# <功能名称> · 分期开发提示词

本目录是“<功能名称>”的分期开发提示词，配合上级目录的《<功能名称>-开发需求文档.md》使用。

## 用法
- 每期单独开一个开发窗口，把对应 `期N-*.md` 的全文作为初始提示词发给 AI。
- 每份提示词都包含“动手前必读”清单，AI 需先读需求文档与现有代码模板。
- 按数字顺序开发；每期完成并验收通过后，再进入下一期。

## 期次总览
| 期 | 文档 | 一句话 |
|---|---|---|

## 全局约束（每期都适用）
- UI 沿用项目现有设计语言。
- 不复制敏感密钥或连接串。
- 风格、命名、目录结构与现有代码保持一致。
- 涉及本地运行时，优先用项目约定的验收方式（{{验收方式}}）真机 / 真环境验证。
```

## 单期提示词结构

每份 `期N-*.md` 按下面结构写：

```markdown
# 期N 开发提示词 · <期次名称>

你是本项目的开发工程师。本期目标：<一句话说清本期闭环>。<明确不做什么、依赖什么、业务价值是什么>。

## 动手前必读
1. 需求文档：`docs/<功能>/<功能>-开发需求文档.md`，重点 §X、§Y。
2. 前期成果：<期1 / 期2 已完成的关键代码或能力>。
3. 现有代码模板：
   - <前端页面 / API>
   - <后端 Controller / Service / Entity>
   - <鉴权 / 白名单 / 打包脚本>

## 前置状态
<写清本期开始前系统应处于什么状态，以及本期不能破坏哪些已完成能力。>

## 任务清单

### A. <云端后端 / 后端数据层>
1. <具体到文件、类、接口、字段、行为>

### B. <本地后端 / 服务 / worker>
1. <具体执行项>

### C. 前端（{{前端}}）
1. <页面、组件、状态、API 封装、交互>

## 数据模型
<如果本期不改表，也要写“复用已有表，无需改结构”。>

## 技术约束与边界
- <不计费 / 密钥只在云端 / 不动旧代码 / 不改数据库等>
- <单条失败不影响整批 / 异步 worker 不在 Controller 里 fire-and-forget>
- <外链、上传、分页、上限、提示等边界>

## 验收
用 {{验收方式}} 起本地环境：
1. <用户从页面入口开始的步骤>
2. <成功状态>
3. <失败 / 异常状态>
4. <下游链路或回归验证>
```

## 期次拆分方法

优先按“风险从低到高、闭环从小到大”拆。

- 期1 写最小闭环：数据表、接口、页面骨架、最简单输入，先让一条数据从入口走到下游。
- 后续期增加输入源、识别、搜索、第三方、批量等能力。
- 旧系统清理单独成期，放在新链路稳定之后。
- 体验打磨单独成期，按价值排序，不混进高风险重构。
- 横向平台扩展单独成期，明确“照搬哪一期架构，只换什么接口 / 来源类型”。

## 必写边界

- 本期不做什么。
- 哪些旧功能不能碰。
- 哪些新功能必须回归。
- 哪些密钥 / 配置不能进不该有的层。
- 哪些接口要加入哪个运行档位白名单（`{{白名单机制}}`；无此机制则忽略）。
- 哪些行为不计费或需要计费。
- 哪些数据必须按当前用户隔离。

## 不同类型期次的额外要求

### 数据地基期

- 写实体、数据上下文、建表脚本、索引、可空字段、用户隔离。
- 写 Controller + Service + API 封装。
- 验收必须包含“重启后数据不丢”和“换账号只看自己的数据”。

### 云端或第三方期

- 写密钥只在云端 / 服务端。
- 写本地端经现有鉴权通道（`{{鉴权方案}}`）调用。
- 写同步 / 异步选择和失败三态。
- 写接口调研结论；未实测就写开发前需确认。

### 批量 / 搜索期

- 写候选列表不落库，用户勾选后才采集 / 处理。
- 写分页 / 游标 / 去重 / 上限。
- 写单条失败不影响整批。
- 写候选外链必须用项目已有打开方式。

### 清理旧体系期

- 先列“必须保留”。
- 再列“删除清单”，按后端、前端、表、脚本、文档分组。
- 要求用 {{结构检索工具}} / 搜索核对依赖，分批删、边删边编译。
- 验收必须包含新链路回归和旧引用全局搜索。

### 体验打磨期

- 按价值排序，可逐项做。
- 不引入新链路。
- 验收用真实页面走查：空态、加载、错误、编辑、批量、筛选、分页。
